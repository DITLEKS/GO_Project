# Пакетный импорт транзакций (тема 10)

`POST /api/transactions/bulk` принимает массив транзакций и обрабатывает его пулом воркеров в Ledger.

## Запрос

- Тело — JSON-массив объектов в том же формате, что и в `POST /api/transactions`: `amount`, `category`, `description`, `date`.
- `?workers=N` — число воркеров, целое от 1 до 8. Без параметра используется значение по умолчанию — 4 (`DefaultImportWorkers`). Верхняя граница 8 (`MaxImportWorkers`) меньше пула соединений PostgreSQL (10).
- Не больше 1000 транзакций и 1 МБ в одном запросе.

```bash
curl -i -X POST 'localhost:8080/api/transactions/bulk?workers=4' \
  -H 'Content-Type: application/json' \
  -d '[
    {"amount":-60,"category":"еда","date":"2026-11-01"},
    {"amount":-60,"category":"еда","date":"2026-11-02"},
    {"amount":0,"category":"еда"},
    {"amount":10,"category":"еда","date":"2026-11-03"}
  ]'
```

## Ответ

При бюджете 100 на категорию «еда» — `200 OK`:

```json
{
  "accepted": 2,
  "rejected": 2,
  "errors": [
    {"index": 1, "error": "budget exceeded"},
    {"index": 2, "error": "сумма транзакции не может быть равна нулю или быть некорректным числом"}
  ]
}
```

- `index` — позиция элемента во входном массиве, с нуля; список отсортирован по `index`.
- Код **200 возвращается и при частичных отказах**, чтобы клиент видел полный отчёт.
- Элементы обрабатываются параллельно, поэтому при нехватке бюджета не гарантируется, какой именно из конкурирующих элементов будет принят: в примере отклонён может быть индекс 0 или 1. Лимит при этом не превышается.
- Импорт не атомарен: принятые транзакции сохраняются, даже если другие отклонены.

| Ситуация | Ответ |
|---|---|
| Все или часть элементов обработаны, включая пустой массив `[]` | 200 и сводка |
| Тело не массив, неизвестное поле, лишние данные после JSON, больше 1000 элементов | 400, `{"error":"…"}` |
| `workers` не целое от 1 до 8 | 400, `{"error":"workers must be an integer from 1 to 8"}` |
| Таймаут или отмена запроса | 504, `{"error":"request timeout"}` |
| Метод не POST | 405, `{"error":"method not allowed"}` |

При 504 часть транзакций уже может быть сохранена. Ledger возвращает в Gateway частичную сводку вместе с ошибкой контекста; Gateway пишет её в лог, а клиенту отдаёт только ошибку таймаута. Таймаут запроса по умолчанию — 2 секунды (`GATEWAY_REQUEST_TIMEOUT`); для больших пакетов его нужно увеличить.

## Как устроен импорт

Код: `ledger/internal/service/import.go`, метод `ImportTransactions(ctx, txs, workers)`.

```
producer -> jobs -> N воркеров -> results -> коллектор
```

1. Основная горутина по одному отправляет элементы с их индексами в канал `jobs` и закрывает его после отправки всех заданий.
2. N воркеров читают `jobs`. Каждый элемент проходит через `AddTransaction`: та же валидация, то же правило бюджета и та же блокировка категории, что и у одиночного POST. Результат с индексом отправляется в `results`.
3. `sync.WaitGroup` ждёт завершения всех воркеров, после чего канал `results` закрывается.
4. Отдельная горутина-коллектор читает `results` и собирает список ошибок. Список изменяет только она, поэтому гонок нет. Коллектор завершается после закрытия `results`.
5. Счётчики `accepted` и `rejected` увеличивают воркеры через `atomic.Int64`.
6. Контекст передаётся во все обращения к БД. Воркеры и отправка заданий проверяют `ctx.Done()` в `select`; при отмене функция дожидается воркеров и коллектора и возвращает частичную сводку и ошибку контекста. Элемент, прерванный отменой, не считается ни принятым, ни отклонённым.

Транзакции одной категории выполняются по очереди из-за блокировки категории, поэтому выигрыш от нескольких воркеров заметен на пакетах с разными категориями.

## Проверка на гонки

```bash
(cd ledger && go test -count=1 -race ./internal/service/...)
(cd gateway && go test -count=1 -race ./...)
```

- `ledger/internal/service/import_test.go` — пул на потокобезопасных фейках: лимит при параллельном импорте, индексы ошибок, разное число воркеров, пустой ввод, прерывание по таймауту.
- `gateway/internal/api/bulk_test.go` — обработчик на заглушке (200, 400, 405, 504) и сквозной сценарий с PostgreSQL и Redis при заданной `TEST_DATABASE_URL`.

CI запускает все тесты обоих модулей с флагом `-race`.
