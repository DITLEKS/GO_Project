# GO_Project

Домашние задания по дисциплине **«Язык Go»**. Требуется Go 1.22 или новее.

## Структура репозитория

```text
.
├── main.go        # ДЗ 1: имя пользователя, CLI-аргументы, версия Go
├── go.mod
├── gateway/       # ДЗ 2: HTTP-шлюз (отдельный Go-модуль)
└── ledger/        # ДЗ 2–3: бизнес-логика транзакций и бюджетов (отдельный Go-модуль)
    ├── main.go              # демонстрационные сценарии
    ├── transaction.go       # Transaction, AddTransaction, ListTransactions
    ├── budget.go            # Budget, SetBudget, LoadBudgets, проверка лимита
    ├── budgets.json         # бюджеты, загружаемые при старте
    ├── transaction_test.go
    └── budget_test.go
```

## ДЗ 1. Введение в Go

```bash
go run . arg1 arg2
```

## ДЗ 2. Функции: Gateway и Ledger

### Gateway

HTTP-сервер на порту 8080, маршрут `GET /ping` возвращает `pong`.

```bash
cd gateway
go run .
```

Проверка в другом терминале:

```bash
curl -i http://localhost:8080/ping
```

Ожидаемый ответ: статус `200 OK` и тело `pong`.

### Ledger

Структура `Transaction` (ID, Amount, Category, Description, Date), хранилище в памяти, функции `AddTransaction` и `ListTransactions`. `AddTransaction` возвращает ошибку при нулевой сумме или пустой категории.

## ДЗ 3. Ввод-вывод (I/O). Обработка ошибок: бюджеты в Ledger

### Что реализовано

- **`Budget`** — структура с полями `Category` (string), `Limit` (float64), `Period` (string, необязательное). Поля имеют JSON-теги `category`, `limit`, `period`.
- **Хранилище бюджетов** — `map[string]Budget`, ключ — название категории. Изначально заполнено примерами: «Продукты» — 5000, «Транспорт» — 2000.
- **`SetBudget(b Budget) error`** — добавляет или обновляет бюджет; возвращает ошибку при пустой категории или лимите ≤ 0. Используется в `main` для установки начальных бюджетов и для изменения лимита.
- **`AddTransaction(tx Transaction) error`** — расширена проверкой бюджета: если для категории расхода задан бюджет и сумма уже потраченного по категории вместе с новой транзакцией превышает `Limit`, возвращается ошибка `ErrBudgetExceeded` (`"budget exceeded"`, обёрнутая через `%w` с деталями), транзакция **не сохраняется**. Расходами считаются транзакции с отрицательной суммой; доходы (положительные суммы) и категории без бюджета не ограничиваются.
- **`SpentByCategory(category string) float64`** — сумма расходов по категории (проход по срезу транзакций).
- **`LoadBudgets(r io.Reader) error`** — читает JSON-массив бюджетов и добавляет их через `SetBudget`. Возвращает понятные ошибки: nil-reader, ошибка чтения, пустой источник, невалидный JSON, невалидный бюджет (с номером элемента).
- В `main` бюджеты загружаются из файла `budgets.json` через `os.Open` + `bufio.NewReader`, демонстрируется обработка ошибок I/O (несуществующий файл, не-массив, отрицательный лимит) и тестовые сценарии: транзакция в пределах лимита, транзакция сверх лимита, повышение лимита через `SetBudget` и повторная попытка.

### Запуск

```bash
cd ledger
go run .
```

Запускать нужно из каталога `ledger`, т.к. `budgets.json` открывается по относительному пути.

### Тесты

```bash
cd ledger
go test ./...
```

Тесты покрывают: добавление/обновление бюджета и валидацию в `SetBudget`; принятие транзакции в пределах лимита и ровно до лимита, отклонение сверх лимита с `errors.Is(err, ErrBudgetExceeded)` и проверку, что отклонённая транзакция не сохранена; доходы и категории без бюджета; `LoadBudgets` на корректном JSON, не-массиве, отрицательном лимите, пустом источнике, ошибке чтения и nil-reader.
